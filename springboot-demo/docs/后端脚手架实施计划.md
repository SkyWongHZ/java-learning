# Spring Boot 后端脚手架实施计划

> 创建日期：2026-07-17  
> 目标项目：`springboot-demo`  
> 当前状态：第一阶段代码、自动化测试和 ECS MySQL公网直连真实 CRUD验收均已完成；local/H2配置已移除

## 1. 建设目标

当前 `springboot-demo` 已经具备 Spring MVC、JSON、参数校验、跨域、请求日志和 MockMvc 测试。本计划将在现有基础上补齐一套可连接真实数据库的后端脚手架，用于练习完整接口开发，并为后续真实业务开发做准备。

第一阶段完成后，应能够通过以下方式操作真实数据库数据：

- Knife4j/Swagger 在线文档
- Postman
- Vue 中的 Axios
- JUnit 5 + MockMvc 自动化测试

本阶段重点是掌握一条完整链路：

```text
HTTP 请求
  → Controller
  → Form 参数校验
  → Service 业务逻辑
  → DAO
  → Mapper
  → MySQL
  → VO
  → Response<T>
  → JSON 响应
```

## 2. 已确定的技术决策

| 项目 | 决策 | 原因 |
| --- | --- | --- |
| Java | Java 17 | 使用当前长期支持版本 |
| Spring Boot | 2.7.18 | 与 Java 17兼容的稳定版本 |
| 单元测试 | 保持 JUnit 5 | 新项目无需复制旧项目的 JUnit 4 兼容配置 |
| Web 测试 | MockMvc | 验证 Controller 到数据库的完整 Spring 链路 |
| 本地运行数据库 | 阿里云 ECS自建 MySQL | 本地 Spring Boot直接连接真实开发数据库 |
| 目标开发数据库 | 用户现有阿里云 ECS自建 MySQL单数据源 | 零增量成本完成真实 MySQL联调，不启用动态数据源 |
| 连接池 | HikariCP | Spring Boot 默认连接池，第一阶段不引入 Druid |
| 持久层 | MyBatis-Plus 3.5.3 | 简化常规 CRUD并保留复杂 SQL扩展能力 |
| 测试数据库 | 与 dev相同的 ECS MySQL | 简化学习环境，不单独建设测试数据库 |
| 接口文档 | Knife4j 3.0.3 + Springfox 3.0.0 | 提供可视化接口文档与调试入口 |
| 简化代码 | Lombok | 减少样板代码 |
| 通用工具 | Hutool 5.8.28 | 按需使用常见工具能力 |
| 统一响应 | `Response<T>` | 统一客户端处理方式 |
| 业务异常 | `BaseException` | 区分业务错误和系统异常 |

### 2.1 JUnit 版本结论

`springboot-demo` 确定继续使用 JUnit 5，不切换到 JUnit 4。

原因：

- Spring Boot 2.7.18 原生支持 JUnit 5。
- JUnit 5 是当前学习项目更合适的测试体系。
- MockMvc 与 JUnit 版本无绑定关系，JUnit 5 可以完整使用 MockMvc。
- 维护已有项目时应遵循所在模块的测试约定；这不要求新学习项目降级到 JUnit 4。

## 4. 数据库设计

### 4.1 数据库和环境配置

```text
数据库名称：springboot_demo
字符集：utf8mb4
排序规则：utf8mb4_unicode_ci
```

当前学习项目可以使用本地 Docker MySQL或用户自己的远程 MySQL；应用层保持标准 JDBC/MyBatis-Plus用法，切换数据库只需替换连接配置。SSH隧道保留为远程连接的可选方式。

任意时刻只启用一个数据源，第一阶段不引入动态数据源结构。

第一阶段实际创建的配置文件：

| 文件 | 职责 |
| --- | --- |
| `application.properties` | 应用名、端口、默认 profile、Jackson、MyBatis-Plus、日志和通用配置 |
| `application-dev.properties` | 通过环境变量和公网地址连接 ECS自建 MySQL |
| `src/test/resources/application-test.properties` | 通过相同环境变量连接 ECS MySQL，只供 JUnit 5使用 |

当前已在真实数据库联调阶段创建 `application-dev.properties`。生产部署尚不存在，因此仍不创建 `application-prod.properties`。

默认 profile：

```properties
spring.profiles.active=${SPRING_PROFILES_ACTIVE:dev}
```

dev和 test都通过环境变量提供同一套 ECS MySQL连接信息：

```text
DB_URL
DB_USERNAME
DB_PASSWORD
```

`DB_URL` 指向 ECS公网 `3306`。ECS地址、数据库用户名和密码只保存在被忽略的本地 `.env` 中。启动应用和执行测试都需要 ECS MySQL可访问。

脚手架实施顺序：

```text
搭建依赖和分层
  → 公网直连接入 ECS MySQL并启用 application-dev.properties
  → dev真实 CRUD与 Knife4j/Postman联调
  → test profile复用 ECS MySQL进行自动化测试
  → 脚手架验收
  → 真正生产部署时创建 application-prod.properties
```

最终 ECS MySQL联调前置条件：

- 查询 ECS上 MySQL服务端版本；当前 `5.7.43` 与 Connector/J `8.0.33`兼容，本阶段不升级8.x。
- 创建 `springboot_demo` 数据库和最小权限开发账号。
- 确认本地能够访问 ECS公网 `3306`。
- 使用 MySQL客户端先验证环境变量对应的账号可以连接。

### 4.2 用户表

表名使用 `demo_user`，避免使用可能产生歧义的 `user`。

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | `bigint` | 主键、自增 | 用户 ID |
| `username` | `varchar(50)` | 非空、唯一 | 登录名/唯一标识 |
| `display_name` | `varchar(100)` | 非空 | 展示名称 |
| `gmt_modify` | `datetime(3)` | 自动更新时间 | 更新时间 |
| `gmt_create` | `datetime(3)` | 默认当前时间 | 创建时间 |
| `deleted` | `tinyint` | 默认 `0` | 逻辑删除：`0` 正常，`1` 删除 |

约定：

- 保存前对 `username` 和 `displayName` 去除首尾空格。
- `username` 使用数据库大小写不敏感规则判重，例如 `Sky` 与 `sky` 视为同一用户名。
- 用户名全局唯一，逻辑删除后也不允许重新使用同名用户名。

MySQL建表 SQL 应独立放在项目 `sql` 目录中，由开发者显式执行，不让应用在 ECS MySQL自动建表。dev和 test直接验证同一份真实 MySQL表结构。

## 5. 代码分层设计

计划包结构：

```text
com.example.springbootdemo
├── config
├── controller
├── dao
│   ├── inter
│   └── impl
├── exception
├── mapper
├── model
│   ├── domain
│   ├── form
│   └── vo
├── service
└── web
```

### 5.1 各层职责

| 层 | 对象 | 职责 |
| --- | --- | --- |
| Domain | `UserDO` | 映射 `demo_user` 表，不直接返回给前端 |
| Mapper | `UserMapper` | 继承 MyBatis-Plus `BaseMapper<UserDO>` |
| DAO | `UserDao` | 封装通用数据库操作和查询条件 |
| DAO实现 | `UserDaoImpl` | 继承 MyBatis-Plus `ServiceImpl` |
| Service | `UserService` | 唯一性校验、存在性校验、事务、DO/VO转换 |
| Form | `CreateUserForm`、`UpdateUserForm` | 接收并校验请求 JSON |
| VO | `UserVO` | 定义前端可见字段 |
| Controller | `UserController` | 路由、参数接收和统一响应，不写业务逻辑 |

简单 CRUD 使用 MyBatis-Plus，不创建无实际 SQL 的 Mapper XML。出现多表关联或复杂统计时再添加 XML。

### 5.2 Hutool使用规范

第一阶段引入 `hutool-all` 5.8.28，用于熟悉常见工具类，但不使用 Hutool替代 Spring Boot 已经明确承担的基础职责。

使用边界：

| 场景 | 约定 |
| --- | --- |
| HTTP入口参数校验 | 继续使用 Hibernate Validator，如 `@NotBlank`、`@Size`、`@Min` |
| Service业务条件 | 可使用 Hutool `Assert`，并通过异常 Supplier抛出 `BaseException` |
| 集合、对象判空 | 按需使用 `CollectionUtil`、`ObjectUtil` |
| 日期处理 | 按需使用 `DateUtil`，数据库时间字段仍使用 `LocalDateTime` |
| JSON序列化 | 继续由 Jackson负责，不在 REST链路中改用 `JSONUtil` |
| DO/Form/VO转换 | 字段较少时显式转换，不为了省代码滥用 `BeanUtil` |
| HTTP、加密、Excel | 第一阶段没有对应需求，不使用 `HttpUtil`、`SecureUtil`、`ExcelUtil` |

业务断言示例：

```java
UserDO user = Assert.notNull(
        userDao.getById(id),
        () -> new BaseException(BaseStatusCodeEnum.USER_DOES_NOT_EXIST)
);
```

用户名唯一性等业务条件同样使用带异常 Supplier 的 Assert，确保异常进入统一的 `BaseException` 处理链，不直接产生无法识别的 `IllegalArgumentException`。

## 6. 接口设计

基础路径：

```text
/api/v1/users
```

### 6.1 创建用户

```http
POST /api/v1/users
Content-Type: application/json
```

请求：

```json
{
  "username": "sky",
  "displayName": "Sky Wang"
}
```

校验：

- `username`：不能为空，长度 2～50字符。
- `displayName`：不能为空，长度 1～100字符。
- `username` 不能与已有记录重复。
- 创建成功统一返回 HTTP `200`，`Response.data` 为创建后的 `UserVO`。

### 6.2 查询用户

```http
GET /api/v1/users/{id}
```

- `id` 必须大于 0。
- 用户不存在或已逻辑删除时返回“用户不存在”业务错误。
- 查询成功时 `Response.data` 为 `UserVO`。

### 6.3 修改用户

```http
PUT /api/v1/users/{id}
Content-Type: application/json
```

请求字段与创建接口一致。修改用户名时，需要排除当前用户后校验唯一性。修改成功统一返回 HTTP `200`，`Response.data` 为修改后的 `UserVO`。

### 6.4 删除用户

```http
DELETE /api/v1/users/{id}
```

- 使用 MyBatis-Plus逻辑删除，不物理删除数据库记录。
- 删除后普通查询不能再获取该用户。
- 第一次删除成功返回 HTTP `200`，`Response.data` 为 `true`。
- 再次删除同一用户返回 HTTP `200`，响应体 `code=9`、`msg=用户不存在`。

### 6.5 用户返回对象

```json
{
  "id": 1,
  "username": "sky",
  "displayName": "Sky Wang",
  "gmtCreate": "2026-07-17 10:00:00",
  "gmtModify": "2026-07-17 10:00:00"
}
```

Jackson统一配置：

```properties
spring.jackson.time-zone=Asia/Shanghai
spring.jackson.date-format=yyyy-MM-dd HH:mm:ss
```

## 7. 统一响应设计

统一响应结构：

```json
{
  "code": "1",
  "msg": "成功",
  "errorDetail": null,
  "data": {},
  "tid": "trace-id"
}
```

字段含义：

| 字段 | 说明 |
| --- | --- |
| `code` | 业务状态码 |
| `msg` | 前端可展示的信息 |
| `errorDetail` | 调试信息；生产环境不得暴露敏感堆栈 |
| `data` | 实际业务数据 |
| `tid` | 日志调用链 ID |

第一阶段状态码：

| code | 说明 |
| --- | --- |
| `1` | 成功 |
| `2` | 通用业务错误 |
| `3` | 系统内部错误 |
| `4` | 参数校验失败 |
| `5` | 参数解析失败 |
| `6` | 不支持的请求方法 |
| `9` | 用户不存在 |

接口路由和 HTTP方法采用 RESTful形式；当前脚手架约定请求进入 Controller后统一返回 HTTP `200`，由响应体 `code` 判断业务结果；不存在的路由仍由 Spring MVC返回 HTTP `404`。

`errorDetail` 第一阶段始终返回 `null`。完整异常信息只写服务端日志，不通过接口响应暴露。

业务失败示例：

```json
{
  "code": "9",
  "msg": "用户不存在",
  "errorDetail": null,
  "data": null,
  "tid": "trace-id"
}
```

## 8. 异常和日志设计

### 8.1 业务异常

新增 `BaseException`，包含：

- 业务错误码
- 用户提示信息
- 开发错误信息

Service 中发现用户名重复、用户不存在等业务问题时抛出 `BaseException`，不在 Controller 中手动拼接错误响应。

### 8.2 全局异常

`@RestControllerAdvice` 统一处理：

- `BaseException`
- `MethodArgumentNotValidException`
- `ConstraintViolationException`
- JSON格式或类型错误
- 不支持的 HTTP方法
- 未预期系统异常

未预期异常必须记录完整日志，但返回给前端的信息不能包含数据库密码、SQL连接信息或完整堆栈。

### 8.3 traceId

- 优先读取请求头 `traceId`；请求头为空时生成新的 traceId。
- traceId 写入 SLF4J MDC。
- 日志记录请求方法、URI、状态和耗时。
- 统一响应的 `tid` 取当前 traceId。
- 响应头返回 `X-Trace-Id`，便于前后端联合排查。
- 请求完成后清理 MDC，避免线程复用导致链路 ID串请求。

## 10. 测试设计

测试继续使用：

```text
JUnit 5
SpringBootTest
MockMvc
ECS MySQL
```

测试数据必须使用唯一业务标识并通过事务回滚，不能依赖执行顺序，也不能清理或修改已有开发数据。

计划覆盖：

- 创建用户成功并写入测试数据库
- 查询用户返回正确 VO
- 修改用户后数据库和接口响应一致
- 删除用户返回 `data=true`，数据库记录被逻辑删除
- 查询不存在、已删除用户或重复删除返回 code `9`
- 重复用户名以及仅大小写不同的用户名返回业务错误
- 用户名前后空格在保存前被移除
- 空用户名、字段超长、非法 ID 返回 code `4`
- 非法 JSON 返回 code `5`
- 响应包含 `tid` 和 `X-Trace-Id`
- 传入请求头 `traceId` 时响应 `tid` 复用该值
- 日期按 `Asia/Shanghai` 和 `yyyy-MM-dd HH:mm:ss` 输出
- Vue 开发域名 CORS继续有效
- Knife4j文档资源可访问
- 原有 `/hello` 测试继续通过

自动验收命令：

```bash
./scripts/test.sh
```

自动测试和真实 MySQL联调都需要 ECS账号、地址和数据库密码。验收步骤如下：

1. 查询 ECS上的 MySQL服务端版本、部署方式和监听端口。
2. 在 ECS MySQL创建 `springboot_demo` 数据库并执行建表 SQL。
3. 设置 `DB_URL`、`DB_USERNAME`、`DB_PASSWORD` 环境变量。
4. 加载 `.env` 并以 dev profile启动 Spring Boot，不额外启动 SSH隧道。
5. 使用 Knife4j或 Postman执行创建、查询、修改和删除。
6. 在 ECS MySQL中确认插入、更新和逻辑删除结果。

## 12. 当前环境和风险

- dev/test都依赖 ECS MySQL和本机网络，ECS不可用时应用和数据库测试无法启动。
- 当前机器未检测到可用 Docker，因此暂不使用 Testcontainers。
- 自动测试会连接共享开发库，必须保持唯一测试数据、事务回滚，并禁止清表或操作已有业务数据。
- MySQL自增序列不会随测试事务回滚，因此测试会造成 ID跳号，但不会保留测试业务记录。
- ECS安全组历史上向全网开放 `3306`；本阶段为加快 Spring Boot CRUD学习暂不调整，旧 Go/Node服务和新应用迁移到 Docker内网后再统一收紧。
- Springfox 与 Spring Boot 2.7需要保留 `ant-path-matcher` 兼容配置。
- 不得复制任何其他项目配置文件中的明文数据库、缓存或第三方密钥。
- 第一阶段每次只实施一个已经确认的阶段，完成后更新本文档状态再继续。

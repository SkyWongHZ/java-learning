## 1. 文档目的

本文档定义学生信息管理系统第一期13个业务接口的请求路径、请求参数、校验规则、响应模型、业务错误码和关键业务语义，作为前端开发、后端 Form/Query/VO 设计、Knife4j 文档和接口测试的共同依据。

本文档不重新设计登录、退出和查询当前管理员接口，只复用脚手架现有登录鉴权能力。

## 3. 公共约定

### 3.1 基础地址

```text
本地开发：http://localhost:18763
业务前缀：/api/v1
```

### 3.2 请求头

除登录接口外，业务接口统一使用以下请求头：

| 请求头 | 必填 | 示例 | 说明 |
| --- | --- | --- | --- |
| `token` | 是 | `8c21...` | 登录成功后返回的服务端会话 Token |
| `system` | 是 | `1` | 客户端系统类型，Web 管理端使用 `1` |
| `traceId` | 否 | `frontend-trace-001` | 前端链路追踪 ID |
| `Content-Type` | POST/PUT必填 | `application/json` | JSON 请求体 |

Token 兼容以下备用格式：

```text
Authorization: Bearer <token>
```

推荐前端统一使用 `token` 请求头，不要同时发送两种 Token。

`system` 的现有取值范围为 `1`～`10`，第一期后台 Web 页面固定使用：

```text
system: 1
```

### 3.3 TraceId

- 如果请求携带 `traceId`，后端继续使用该值。
- 如果未携带，后端自动生成 TraceId。
- 响应头返回 `X-Trace-Id`。
- 响应体 `tid` 与响应头 `X-Trace-Id` 保持一致。

### 3.4 日期时间

日期时间统一返回字符串：

```text
yyyy-MM-dd HH:mm:ss
```

示例：

```text
2026-07-26 14:30:45
```

时区统一为 `Asia/Shanghai`。

### 3.5 业务编码

以下编码保存前统一执行：

```text
去除首尾空格 → 英文字母转换为大写 → 判重 → 保存
```

适用字段：

- `studentNo`
- `courseCode`
- `classCode`

响应中返回转换后的最终值。

## 4. 统一响应

### 4.1 响应结构

所有已进入 Controller 和统一异常处理流程的业务请求使用：

```json
{
  "code": 1,
  "msg": "成功",
  "errorDetail": null,
  "data": {},
  "tid": "frontend-trace-001"
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | `Integer` | 业务状态码，`1`表示成功 |
| `msg` | `String` | 面向用户或前端的提示 |
| `errorDetail` | `String/null` | 预留错误详情；对外响应通常为 `null` |
| `data` | `Object/null` | 业务数据；失败时为 `null` |
| `tid` | `String` | TraceId |

### 4.2 HTTP 状态码

沿用当前脚手架约定：

- 成功、参数校验错误和已知业务错误通常返回 HTTP `200`。
- 前端必须以响应体 `code` 判断业务是否成功。
- 不存在的路由返回 HTTP `404`。
- 未进入统一异常处理的容器级错误可能返回其他 HTTP 状态码。

### 4.3 成功响应

```json
{
  "code": 1,
  "msg": "成功",
  "errorDetail": null,
  "data": true,
  "tid": "f53c9ce527684b12a7df02120296510b"
}
```

### 4.4 失败响应

```json
{
  "code": 2,
  "msg": "学生不存在",
  "errorDetail": null,
  "data": null,
  "tid": "f53c9ce527684b12a7df02120296510b"
}
```

## 5. 分页约定

### 5.1 分页请求

| 参数 | 类型 | 必填 | 默认值 | 规则 |
| --- | --- | --- | --- | --- |
| `pageNum` | `Integer` | 是 | 无 | 最小值 `1` |
| `pageSize` | `Integer` | 是 | 无 | 最小值 `1` |

该约定只适用于学生分页查询，并与 `bjsm-cloud` 的 `BaseQuery` 保持一致。分页接口不定义 `all` 参数，也不把 `pageSize = 0`、负数或超大固定值解释为“查全部”。

### 5.2 分页响应

```json
{
  "pageNum": 1,
  "pageSize": 10,
  "total": 0,
  "pages": 0,
  "list": [],
  "boolLastPage": true
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `pageNum` | `Integer` | 当前页码 |
| `pageSize` | `Integer` | 每页数量 |
| `total` | `Long` | 总记录数 |
| `pages` | `Integer` | 总页数 |
| `list` | `Array<T>` | 当前页数据，无数据时返回 `[]` |
| `boolLastPage` | `Boolean` | 是否为最后一页 |

学生查询不传 `keyword`、`classId`、`courseId` 等业务筛选条件，只表示对全部学生数据范围进行分页查询，并不表示一次返回全部学生。

学生分页接口默认按照：

```text
gmtCreate DESC, id DESC
```

排序，确保创建时间相同时结果稳定。

### 7.3 新增学生

```http
POST /api/v1/students
Content-Type: application/json
```

#### CreateStudentForm

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| `studentNo` | `String` | 是 | 去除首尾空格后长度 `2`～`32`，全局唯一，英文字母转大写 |
| `name` | `String` | 是 | 去除首尾空格后长度 `1`～`50` |
| `gender` | `Integer` | 是 | 只能为 `0`、`1`、`2` |
| `phone` | `String` | 否 | 空白转 `null`；非空时为中国大陆11位手机号 |
| `classId` | `Long` | 是 | 大于 `0`，班级必须存在且未删除 |
| `courseIds` | `Array<Long>` | 否 | 未传、`null`或`[]`均表示不选课程；元素不能为`null`，ID大于`0`且不能重复 |

手机号第一期校验规则：

```text
^1[3-9]\d{9}$
```

请求示例：

```json
{
  "studentNo": " s2026001 ",
  "name": " 张三 ",
  "gender": 1,
  "phone": "13800138000",
  "classId": 1,
  "courseIds": [10, 20]
}
```

处理结果：

- `studentNo` 保存为 `S2026001`。
- `name` 保存为 `张三`。
- 学生、班级和课程关联校验及写入在同一事务中完成。
- 任一班级或课程无效时，学生和课程关系均不落库。

成功时返回 `StudentDetailVO`。

### 7.4 修改学生

```http
PUT /api/v1/students/{id}
Content-Type: application/json
```

修改接口使用完整更新语义。

#### UpdateStudentForm

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| `name` | `String` | 是 | 去除首尾空格后长度 `1`～`50` |
| `gender` | `Integer` | 是 | 只能为 `0`、`1`、`2` |
| `phone` | `String` | 否 | 未传、`null`或空白均表示清空手机号 |
| `classId` | `Long` | 是 | 大于 `0`，班级必须存在且未删除 |
| `courseIds` | `Array<Long>` | 是 | 必须出现且不能为`null`；允许`[]`；元素不能为`null`，ID大于`0`且不能重复 |

`studentNo` 不属于修改字段，前端不得在修改请求中发送。

`courseIds` 语义：

| 请求值 | 处理方式 |
| --- | --- |
| `[10, 20]` | 最终课程集合完整替换为课程10和20 |
| `[]` | 清空全部课程 |
| 未传或 `null` | 参数校验失败 |

请求示例：

```json
{
  "name": "张三",
  "gender": 1,
  "phone": null,
  "classId": 2,
  "courseIds": [10]
}
```

学生基础信息和课程集合必须在同一事务中更新。任一校验或写入失败时，全部回滚。

成功时返回更新后的 `StudentDetailVO`。

### 7.5 删除学生

```http
DELETE /api/v1/students/{id}
```

处理规则：

- 逻辑删除学生。
- 在同一事务中物理删除该学生的全部课程关联。
- 删除后原学号仍被占用。
- 重复删除按学生不存在处理。

成功响应：

```json
{
  "code": 1,
  "msg": "成功",
  "errorDetail": null,
  "data": true,
  "tid": "f53c9ce527684b12a7df02120296510b"
}
```

## 10. 业务错误码

### 10.1 现有公共错误码

| code | 名称 | msg |
| ---: | --- | --- |
| `1` | `SUCCESS` | 成功 |
| `2` | `BUSINESS_ERROR` | 业务处理失败 |
| `3` | `SYSTEM_ERROR` | 系统异常，请稍后重试 |
| `4` | `VALIDATION_ERROR` | 请求参数校验失败，实际 `msg` 优先返回具体字段提示 |
| `5` | `JSON_PARSE_ERROR` | 请求体格式错误 |
| `6` | `METHOD_NOT_SUPPORTED` | 请求方法不支持 |
| `8` | `USER_NOT_LOGGED_IN` | 用户未登录 |
| `11` | `LOGIN_EXPIRED` | 登录已过期 |

### 10.2 业务错误信息

学生、班级和课程模块不新增细分业务状态码。以下已知业务失败统一返回 `code = 2`，通过 `msg` 返回具体原因：

| code | msg | 使用场景 |
| ---: | --- | --- |
| `2` | 学生不存在 | 查询、修改、删除不存在或已删除学生 |
| `2` | 学号已存在 | 新增学生学号重复 |
| `2` | 班级不存在 | 关联、修改、删除不存在或已删除班级 |
| `2` | 班级编码已存在 | 新增或修改班级编码重复 |
| `2` | 班级下仍有学生，不能删除 | 删除被学生使用的班级 |
| `2` | 课程不存在 | 关联、修改、删除不存在或已删除课程 |
| `2` | 课程编码已存在 | 新增或修改课程编码重复 |
| `2` | 课程仍被学生选择，不能删除 | 删除被学生选择的课程 |

以下情况统一返回 `code = 4` 和具体校验提示：

- `courseIds` 出现重复值。
- `courseIds`、`classId` 或 Path ID 小于等于 `0`。
- `pageNum` 或 `pageSize` 未传、为 `null` 或小于 `1`。
- 性别枚举非法。
- 手机号格式非法。
- 必填字段为空。
- 修改学生时 `courseIds` 未传或为 `null`。

数据库唯一索引或外键并发冲突应由后端转换为 `code = 2`。能够识别具体原因时返回对应 `msg`；无法安全识别时返回“数据已存在或违反数据库约束”，不得直接返回数据库约束名称。

## 12. 后端模型建议

### 12.1 Query

只有 `StudentPageQuery` 继承 `BaseQuery`。`BaseQuery` 只定义必填的 `pageNum` 和 `pageSize`；不复制 `bjsm-cloud` 中与医院权限有关的 `manageHospitalList` 字段。`CourseQuery` 和 `ClassQuery` 只定义可选的 `keyword`，不包含分页字段。

### 12.2 Form

```text

```

### 12.3 VO

```text

CourseSimpleVO

```

Query、Form、VO 不直接复用数据库 DO，避免数据库字段和前端接口互相绑定。

### 12.4 校验实现注意事项

- 业务编码和名称必须先去除首尾空格，再校验规范化后的长度。
- 仅依赖 `@Size` 会在去除空格前执行，Service 层仍需校验规范化后的最终值。
- `UpdateStudentForm.courseIds` 使用 `@NotNull`，列表元素必须非空且大于`0`。
- 课程 ID 重复校验可在 Service 层通过集合去重完成。
- 手机号为空白时转换为 `null`；非空时按本文档正则校验。

## 15. 开发实现约定

学生分页实现按照 `bjsm-cloud` 的做法使用 PageHelper，不使用 MyBatis-Plus 分页拦截器。项目已经配置：

```text
com.github.pagehelper:pagehelper-spring-boot-starter:1.4.7
```

Service 分页流程统一为：

```java
PageHelper.startPage(query.getPageNum(), query.getPageSize());
List<DO> rows = dao.queryList(query);
PageInfo<DO> pageInfo = new PageInfo<>(rows);
return PageWrapper.convert(pageInfo, voList);
```

`PageHelper.startPage` 必须紧邻其负责分页的 Mapper 查询，避免线程上下文中的分页参数影响其他 SQL。

学生分页同时支持班级和课程筛选，建议使用自定义 Mapper SQL：

- 使用 `EXISTS` 判断学生是否选择指定课程，避免普通 JOIN 造成学生记录重复。
- 所有学生、班级和课程查询必须过滤逻辑删除数据。
- 查询已逻辑删除记录占用的业务编码时，需要使用不受 MyBatis-Plus逻辑删除自动条件影响的专用 Mapper SQL。
- 新增 `PageWrapper<T>`，字段与 `bjsm-cloud` 保持一致：`pageNum`、`pageSize`、`total`、`pages`、`list`、`boolLastPage`。
- PageHelper 只用于学生分页查询。
- 课程和班级查询不调用 PageHelper，分别直接返回 `List<CourseVO>` 和 `List<ClassVO>`，无数据时返回空数组。
- 不直接向前端返回 `PageInfo`、MyBatis-Plus `IPage` 或 DO。
